10) PO/Recommendation Duplicate Submission & Status Fix
==================================================
Issue:
- After first recommendation/process, action still appeared again in vendor quotation modal.
- Also mismatch seen between /sp/quotations and /quotation/{id}/vendor-quotations screens.

Root cause:
- Some logic checked only Recommendation table.
- Some logic relied only on qr_id approvals; legacy/alternate records can be linked through po_id.
- Header sometimes showed View PO even when PO number not generated yet.

Fixes implemented:
- Controller guard strengthened in QuotationRequestController@storeRecommendationAndPO:
  - Blocks duplicate submission if any of these exists:
    - approvals by qr_id
    - approvals by linked po_id
    - existing recommendation for qr_id
    - existing purchase order for qr_id
  - Returns 409 with already_submitted marker for frontend handling.
- QuotationRequestController@viewVendorQuotations:
  - approvalAlreadySubmitted now checks both qr_id and linked po_id.
- related_vendor_quotations.blade.php:
  - Action rendering updated:
    - show Process only when not already submitted and no recommendation/PO complete state
    - show "Already Recommended" badge when approval flow already exists
  - Submit button hardening:
    - disable while request in flight
    - prevent double click
    - handle 409 duplicate response cleanly
  - Header PO display corrected:
    - show "View PO: <po_no>" only when po_status == generated and po_no exists
    - otherwise show "PO Pending Generation"

Validation done:
- PHP syntax check passed for QuotationRequestController.php
- No linter errors on edited files
